# SPEC-UX-001: UX 분석 및 개발 방향

AEC Character Generator 앱의 UX 개선을 위한 경쟁 분석, 격차 진단, 구현 전략 및 향후 방향을 정리한 문서이다.

---

## 1. 경쟁 앱 분석

AEC Character Generator의 핵심 기능인 **아바타 캐릭터 생성 + 일일 기분 일기**와 직접적으로 경쟁하는 4개 앱을 분석하였다.

| 앱 | 핵심 UX 특징 | 강점 |
|-----|-------------|------|
| **Daylio** | 2-tap 기분 기록, 컬러 달력, 통계 대시보드 | 극도의 단순함, "Year in Pixels" 시각화로 연간 감정 패턴을 한눈에 파악 |
| **Finch** | 캐릭터 기반, 부드러운 온보딩, 게이미피케이션 | 반려 캐릭터를 통한 정서적 유대감 형성, 자기돌봄 습관화 |
| **Pixels** | 컬러 그리드 달력, 최소 UI, 기분 패턴 분석 | 시각적 단순미, 색상만으로 감정 변화를 즉시 인식 가능 |
| **Zepeto** | 아바타 커스터마이징, 풍부한 에셋 라이브러리 | 깊은 개인화 경험, 수천 가지 조합으로 자기 표현 |

### 경쟁 앱에서 배울 수 있는 핵심 패턴

- **Daylio/Pixels**: 색상 기반 달력 시각화는 사용자가 자신의 감정 추세를 직관적으로 파악할 수 있게 하여 장기 사용을 유도한다.
- **Finch**: 앱의 가치를 먼저 설명하는 온보딩이 신규 사용자 이탈률을 낮춘다.
- **Daylio**: 저장까지의 탭 수를 최소화하면 일일 기록 완료율이 높아진다.
- **Zepeto**: 풍부한 에셋을 통한 캐릭터 개인화가 사용자 애착을 형성한다.

## 2. 현재 앱 UX 격차 분석

SPEC-UX-001 구현 **이전** 시점에서 식별된 3가지 핵심 격차를 문서화한다.

### Gap 1: 달력 시각화

| 항목 | 내용 |
|------|------|
| **개선 전** | 회색 그리드에 작은 이모지만 표시되어 감정 패턴을 한눈에 파악하기 어렵다 |
| **경쟁사 벤치마크** | Daylio/Pixels는 날짜별 색상 코딩으로 즉각적인 패턴 인식을 지원한다 |
| **영향** | 사용자가 월별/연간 감정 추세를 빠르게 이해하지 못해 앱의 장기 가치를 체감하지 못한다 |

### Gap 2: 기분 기록 흐름

| 항목 | 내용 |
|------|------|
| **개선 전** | 저장 버튼의 시각적 강조가 부족하고, 부가 액션(의상 선택, 다시 뽑기)이 동일한 비중으로 표시된다 |
| **경쟁사 벤치마크** | Daylio는 2-tap으로 기록을 완료하며, 저장 버튼이 지배적인 CTA로 배치된다 |
| **영향** | 사용자가 주요 액션(저장)과 부가 액션을 구분하지 못해 혼란을 느끼거나 저장을 놓칠 수 있다 |

### Gap 3: 온보딩

| 항목 | 내용 |
|------|------|
| **개선 전** | 회원가입 후 아무런 소개 없이 캐릭터 생성 위자드로 바로 진입한다 |
| **경쟁사 벤치마크** | Finch는 부드러운 온보딩으로 앱의 가치를 먼저 설명한 후 기능으로 안내한다 |
| **영향** | 신규 사용자가 앱의 핵심 가치(캐릭터 + 기분 일기 + 감정 패턴 발견)를 이해하지 못한다 |

## 3. Phase 1 개선 전략

3가지 P0 모듈을 구현하여 위 격차를 해소하였다.

### Module 1: 달력 색상 시각화

**문제**: 이모지만으로는 월별 감정 패턴을 한눈에 파악할 수 없다.

**해결**: 7개 MoodCategory별 고유 색상을 달력 셀 배경에 적용하여 "Year in Pixels" 스타일의 시각화를 구현하였다.

**MOOD_COLOR_MAP 색상 매핑:**

| MoodCategory | 색상명 | 배경 | 텍스트 | 도트 |
|-------------|--------|------|--------|------|
| happy | Yellow | `bg-yellow-200` | `text-yellow-900` | `bg-yellow-400` |
| confident | Orange | `bg-orange-200` | `text-orange-900` | `bg-orange-400` |
| calm | Blue | `bg-blue-200` | `text-blue-900` | `bg-blue-400` |
| surprised | Purple | `bg-purple-200` | `text-purple-900` | `bg-purple-400` |
| thoughtful | Indigo | `bg-indigo-200` | `text-indigo-900` | `bg-indigo-400` |
| playful | Pink | `bg-pink-200` | `text-pink-900` | `bg-pink-400` |
| determined | Red | `bg-red-200` | `text-red-900` | `bg-red-400` |

**기술적 접근:**

- 200-level 배경 + 900-level 텍스트 조합으로 WCAG AA 대비율(4.5:1 이상)을 확보하였다.
- 선택된 날짜 셀은 기존 파란색 배경(`bg-blue-500`)을 유지하고, 기분 색상은 작은 도트 인디케이터로 표시한다.
- 색맹 사용자를 위해 이모지를 색상과 함께 유지하였다.
- 모든 기분 기록 셀에 `aria-label`로 기분 카테고리의 한국어명을 포함하였다.

### Module 2: 기분 기록 간소화

**문제**: 저장 버튼과 부가 액션의 시각적 계층이 불분명하다.

**해결**: 레이아웃을 재구성하여 저장 버튼을 주요 CTA로 강조하고, 부가 옵션을 접이식 섹션으로 분리하였다.

**레이아웃 변경 (기분 기록 페이지):**

```
[캐릭터 미리보기]
[기분 카테고리 선택]       -- 항상 보임
[======= 저장 버튼 =======] -- 주요 CTA, 전체 너비, 강조
[세부 조정 (접기/펼치기)]   -- 기본 접힘
  +-- 의상 카테고리 선택
  +-- 표정 다시 뽑기
  +-- 의상 다시 뽑기
[다운로드 (보조)]           -- outline 스타일
```

**구현 세부사항:**

- **Primary CTA**: `w-full py-4 text-lg font-bold bg-blue-600` 스타일로 저장 버튼을 기분 선택 바로 아래에 배치하였다.
- **접이식 섹션**: HTML5 `<details>`/`<summary>` 태그를 사용하여 추가 React 상태 없이 접기/펼치기를 구현하였다.
- **다운로드 버튼**: `border border-gray-300 text-gray-600 bg-white` outline 스타일로 보조 액션임을 시각적으로 표현하였다.
- **선택 애니메이션**: 기분/의상 카드 선택 시 `scale-105` 전환 효과를 적용하였다.

### Module 3: 온보딩 플로우

**문제**: 신규 사용자가 앱의 핵심 가치를 모른 채 캐릭터 생성을 시작한다.

**해결**: 캐릭터 위자드 진입 전 3-slide 온보딩 시퀀스를 표시하여 앱의 핵심 가치를 전달한다.

**슬라이드 구성:**

| Slide | 제목 | 설명 | 아이콘 |
|-------|------|------|--------|
| 1 | 나만의 캐릭터 만들기 | 498개 에셋으로 세상에 하나뿐인 캐릭터를 만들어보세요 | 캐릭터 SVG |
| 2 | 매일 기분 기록하기 | 오늘의 기분을 선택하면 캐릭터가 표정과 의상을 바꿔요 | 달력 SVG |
| 3 | 감정 패턴 발견하기 | 색상 달력에서 나의 감정 변화를 한눈에 확인하세요 | 차트 SVG |

**구현 세부사항:**

- 인라인 SVG 아이콘을 사용하여 외부 아이콘 라이브러리 의존성을 제거하였다.
- `localStorage` 키 `aec_onboarding_done`으로 완료 상태를 관리한다.
- "건너뛰기" 버튼을 모든 슬라이드에서 제공한다.
- 관리자(`isAdmin`)는 온보딩을 완전히 건너뛴다.
- 키보드 내비게이션 지원: `ArrowLeft`(이전), `ArrowRight`/`Enter`(다음), `Escape`(건너뛰기).
- `localStorage` 접근 실패 시 `try-catch`로 graceful degradation을 보장한다.

## 4. 기술 결정 사항

| 결정 | 선택 | 근거 |
|------|------|------|
| 새로운 라이브러리 미추가 | Tailwind CSS 4 + React 19만 사용 | 번들 크기 최소화, 기존 스택 활용 극대화 |
| 정적 색상 매핑 | `MOOD_COLOR_MAP` 상수 정의 | Tailwind CSS purge 시 동적 클래스명이 제거되는 문제를 방지 |
| HTML5 details/summary | 네이티브 접이식 섹션 사용 | 추가 React 상태 불필요, 접근성 내장 |
| localStorage 온보딩 상태 | 클라이언트 사이드 상태 관리 | Firebase 스키마 변경 불필요 |
| 인라인 SVG 아이콘 | 컴포넌트에 직접 임베드 | 아이콘 라이브러리 의존성 제거, 완전한 커스터마이징 가능 |
| 200-level bg + 900-level text | WCAG AA 대비율 확보 | 모든 기분 색상에서 텍스트 가독성 보장 |
| try-catch localStorage 접근 | Graceful degradation | SSR 환경 안전, localStorage 비활성화 시 오류 방지 |

## 6. 향후 개발 방향

### Phase 2 후보 (P1 우선순위)

| 기능 | 설명 | 기대 효과 |
|------|------|----------|
| **기분 통계 대시보드** | 주간/월간 기분 분포 차트, 가장 빈번한 감정 통계 | 자기 인식 강화, Daylio 수준의 인사이트 제공 |
| **기분 연속 기록 (Streak)** | 연속 기록일 트래커 + 게이미피케이션 보상 | 일일 기록 습관 형성, 리텐션 향상 |
| **캐릭터 애니메이션** | 기분에 따른 미묘한 idle 애니메이션 (행복=흔들기, 차분=호흡) | 캐릭터에 대한 정서적 유대감 강화 |
| **소셜 공유** | 기분 캐릭터를 이미지로 SNS에 공유 | 바이럴 성장, 유저 획득 비용 절감 |

### Phase 3 후보 (P2 우선순위)

| 기능 | 설명 | 기대 효과 |
|------|------|----------|
| **AI 기분 인사이트** | 감정 패턴 분석 및 추세 제안 (예: "화요일에 기분이 좋은 편이에요") | 데이터 기반 자기 이해, 차별화 요소 |
| **커스텀 기분 카테고리** | 기본 7개 외 사용자 정의 기분 유형 추가 | 개인화 심화, 다양한 감정 표현 |
| **테마 시스템** | 다크 모드, 계절 테마, 사용자 커스텀 색상 | 시각적 다양성, 사용자 선호 반영 |
| **홈 화면 위젯** | 오늘의 캐릭터를 보여주는 홈 화면 위젯 | 앱 접근성 향상, 일일 기록 유도 |

### 기술 부채

| 항목 | 설명 | 우선순위 |
|------|------|---------|
| 온보딩 상태 마이그레이션 | `localStorage`에서 Firebase로 이전하여 기기 간 동기화 지원 | 중간 |
| E2E 테스트 추가 | 온보딩 플로우 및 달력 색상 렌더링에 대한 E2E 테스트 작성 | 높음 |
| 성능 프로파일링 | 365개 이상 항목이 있는 달력의 렌더링 성능 측정 및 최적화 | 낮음 |
